# 소셜 투표 서비스 데이터 파이프라인

🔗 [파이프라인 다이어그램](https://claude.ai/code/artifact/958167e6-cd4d-4cbd-a452-f6edd772e431) | [데이터 대시보드](https://lookerstudio.google.com/reporting/56421d8f-e6cc-4303-8e86-76b5d31cb55c/page/p_bc34jacl6d) | [ERD](https://mermaid.ai/d/2fc1853e-0a60-400f-a00e-6a27bab52448)

## 개요

* 목표: 사용자 이탈 원인 분석을 위한 데이터 구조 및 파이프라인 구축
  → 가입·결제 등 서비스 현황을 지속적으로 모니터링할 수 있는 분석 기반(파이프라인·대시보드) 구축
* 기간: 2026.07.23 ~ 2026.08.27
* 팀: 데이터 분석가 5명
* 데이터: 2023.03 ~ 2024.05 (1년 3개월, 실제 운영 데이터) / 합성 데이터 2만 명·12개월치
* 문제: 가입자의 63.9%가 가입 후 일주일 이내 활동 중단
  * 가입자 677,085명 중 63.9%가 가입 후 7일 이내(가입일 D0 ~ D+6) 이탈
  * 로그인 기록이 없어, 가입자의 95.9%가 1회 이상 보낸 친구요청 발신 로그를 활동 지표로 사용
* 데이터 한계: 투표 데이터가 10개 학교에만 존재하여 이탈 원인 분석에 제약
  * 투표 데이터 제공 범위: 5,951개 중 10개 학교 (나머지는 마스킹)
  * 월 투표 참여자 약 400명 → 성별·기기별로 나누면 구간당 100명 미만
  * 투표 데이터가 있는 결제자: 59,192명 중 약 410명 (0.7%)
  * 결제·투표 데이터의 user_id 체계가 달라 사용자 단위 연결이 어려움

## 내 역할

* 로그인 기록이 없어 친구요청 발신 로그를 활동 지표로 삼아 이탈 정의
* ERD와 파이프라인 구조도로 데이터 흐름 문서화

## 분석 과정

1. 레거시 서비스 데이터 구조 및 이탈 현황 분석
2. 합성 데이터 생성 (기존 비율 유지, 약 4배 확장 · 총 2만 명)
3. Raw → Staging → Mart 데이터 구조 설계 (대시보드 지표를 먼저 정하고 Mart를 역산 설계)
4. Airflow 기반 데이터 적재 및 집계 자동화
5. Looker Studio 대시보드 구축 (핵심 지표 · 단계별 전환율 · 운영 알림)

## 주요 결과

* 실제·합성 데이터를 동일한 구조로 관리하고 `_source`, `_loaded_at`으로 데이터 구분
* Raw 원천 데이터 적재 → Staging View 10개 → Mart 집계 테이블 8개로 데이터 계층화
* Airflow 2개 DAG으로 Raw 적재부터 Mart 생성까지 자동화

## 사용 기술

* BigQuery, Airflow, Python (Pandas), MySQL, PostgreSQL, Supabase, Looker Studio
